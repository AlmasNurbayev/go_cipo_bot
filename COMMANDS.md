# Команды и кнопки бота

Справочник по всему, что понимает Telegram-бот Cipo: слэш-команды, кнопки клавиатуры, текстовые запросы и inline-кнопки под сообщениями.

Регистрация хендлеров — в `init.go` каждого модуля `internal/botP/<модуль>/`, список модулей — `BotApp.Run()` в `internal/botP/bot.go`.

## Доступ

- Писать боту может только пользователь из таблицы `users` (сверка по `telegram_id`). Остальным бот отвечает «👎 User not authorized».
- Роль `kaspi_manager` получает только уведомления о продажах Kaspi-товаров. На любую команду бот отвечает «ℹ️ Вам доступны только уведомления о продажах Kaspi-товаров».
- Роль `admin` нужна для отправки тестового сообщения (`other_sendTestMessage`). Администраторам также приходит предупреждение, если NATS недоступен.
- `middleware.CheckUser` проверяет только текстовые сообщения, **нажатия inline-кнопок он не проверяет**. Отдельную проверку роли делает только кнопка `other_sendTest_`.
- Если сообщение не подходит ни под одну команду, бот отвечает «Сообщение не распознано».

## Сводка

| Команда | Модуль | Что открывает |
|---|---|---|
| `/summary` | summary | клавиатура «итоги …»: продажи за период |
| `/charts` | charts | клавиатура «график …»: графики продаж |
| `/qnt` | qnt | клавиатура «остатки …»: текущие остатки |
| `/finance` | finance | клавиатура «финансы …»: ОПиУ из Google Sheets |
| `/other` | other | служебные команды |

Команды нужно отправлять точно как в таблице. Все клавиатуры сворачиваются после нажатия кнопки (`OneTimeKeyboard`). Кнопка отправляет свой текст обычным сообщением, поэтому тот же текст можно набрать вручную.

## `/summary`: итоги продаж

Кнопки клавиатуры:

| | |
|---|---|
| `итоги тек. день` | `итоги пр. день` |
| `итоги тек. неделя` | `итоги пр. неделя` |
| `итоги тек. месяц` | `итоги пр. месяц` |
| `итоги тек. квартал` | `итоги пр. квартал` |
| `итоги тек. год` | `итоги пр. год` |
| `итоги произ. дата` | |

Подходит любое сообщение, которое начинается со слова «итоги» (регистр не важен, регэксп `(?i)^итоги.*`). Период определяет `utils.GetPeriodByMode`:

| Текст | Период |
|---|---|
| `итоги тек. …` / `итоги пр. …` | текущий / предыдущий день, неделя (с понедельника), месяц, квартал или год |
| `итоги 2024` | календарный год |
| `итоги 2024 08` | месяц |
| `итоги 2024 08 21` | конкретный день |
| `итоги произ. дата` | бот присылает подсказку по формату выше |

Бот отвечает сводкой за период:
- количество чеков;
- чистая сумма продаж с разбивкой на кеш, карту, смешанную оплату и прочее;
- сумма продаж и сумма возвратов;
- разбивка по кассам (если касс больше одной);
- выемки, внесения и остаток наличных в кассах.

### Inline-кнопки под сводкой

| Кнопка | `callback_data` | Что делает |
|---|---|---|
| 🔍 Все чеки | `summary_allChecks_<от>_<до>` | список чеков текстом с кнопками-номерами для открытия каждого чека; длинный список режется на части по 4096 символов |
| Все чеки # | `summary_allChecksTable_<от>_<до>` | таблица: № / дата-время / тип / сумма / в т.ч. карта / в т.ч. нал. Отправляется rich-сообщением, по 40 строк; под каждой частью кнопки-номера (до 5 рядов по 8). Если rich-сообщения не поддерживаются, та же таблица приходит моноширинным блоком |
| Аналитика | `summary_analytics_<от>_<до>` | аналитика по товарам за период: скидки, возвраты и сумма чеков, которые в аналитику не попали |
| Диаграмма по дням | `summary_chartsDay_<от>_<до>` | ⚠️ обработчик не реализован, кнопка ничего не делает |

Даты в `callback_data` передаются в формате `YYYY-MM-DD`.

Обе кнопки «Все чеки» показываются, только если период не длиннее `SUMMARY_CHECKS_MAX_DAYS` дней. Значение берётся из таблицы `app_settings`, по умолчанию 7. Для месяца и года этих кнопок нет. Если нажать кнопку в старом сообщении, где период уже превышает лимит, бот ответит текстом с текущим лимитом.

### Кнопки открытия чека

| Кнопка | `callback_data` | Где появляется | Что делает |
|---|---|---|---|
| номер чека (`1`, `2`, …) | `getCheck_<id>` | списки «Все чеки» | карточка чека: состав и фото товаров с сайта cipo.kz. Если фото есть, чек приходит медиагруппой |
| `чек №<id> / <сумма>₸` | `getCheck_<id>` | NATS-уведомления о новых операциях | то же |
| Полный текст чека / Открыть | `getFullTextCheck_<id>` | под карточкой чека | исходный текст чека из КОФД |

Telegram не разрешает прикреплять inline-кнопки к медиагруппе. Поэтому для чека с фото кнопка «Открыть» приходит отдельным сообщением «Полный текст чека».

## `/charts`: графики продаж

| Кнопка | Что присылает |
|---|---|
| `график 30 дней` | продажи за последние 30 дней в сравнении с тем же периодом год назад; в подписи обе суммы |
| `график этот год` | текущий год в сравнении с прошлым; в подписи обе суммы |
| `график 12 месяцев` | последние 12 месяцев, по каждому месяцу две колонки: этот год и год назад |

Хендлер ловит любой текст, который начинается со слова «график», но ответ приходит только на эти три фразы, набранные точно. На любой другой такой текст бот ничего не отвечает.

## `/qnt`: остатки товаров

| Кнопка | Группировка |
|---|---|
| `остатки сейчас по сезону` | по сезонам |
| `остатки сейчас по виду модели` | по виду модели |

Остатки запрашиваются с бэкенда cipo.kz (данные из 1С Розница). Ответ: магазины и товары по группам с количеством и суммами; длинный ответ режется на части по 4096 символов. Хендлер срабатывает на любой текст, который начинается с одной из этих фраз.

## `/finance`: финансы (ОПиУ)

| | |
|---|---|
| `финансы тек. месяц` | `финансы пр. месяц` |
| `финансы тек. квартал` | `финансы пр. квартал` |
| `финансы тек. год` | `финансы пр. год` |
| `финансы произ. дата` | `финансы диаграмма тек.год` |

Подходит любой текст, который начинается со слова «финансы» (регистр не важен). Периоды разбираются так же, как в `/summary`: `финансы 2024`, `финансы 2024 08`, а также `тек.`/`пр.` с днём и неделей, которых нет на клавиатуре.

- **Отчёт за период.** Бот присылает картинку-таблицу ОПиУ (доходы, расходы, прибыль) с подписью. Данные берутся из Google Sheets. Если выручки за месяц в таблице нет, она берётся из кассовых чеков.
- **`финансы диаграмма тек.год`.** Диаграмма по месяцам текущего года. Срабатывает на любой текст со словом «диаграмма», период всегда текущий год.
- **`финансы произ. дата`.** Бот присылает подсказку по формату.

Настройки лежат в `app_settings`: `FINANCE_GHEETS_SOURCES`, `FINANCE_OPIU_REVENUE_ITEMS`, `FINANCE_OPIU_COST_ITEMS`, `FINANCE_OPIU_SPECIAL_ITEMS`, `FINANCE_USD_RATE`, `FINANCE_PLANNING_MARGIN`.

## `/other`: служебные команды

| Кнопка | Доступ | Что делает |
|---|---|---|
| `other_siteParserJSONlog` | все пользователи | последние запуски JSON-парсера сайта из `SITE_PARSER_JSON_LOG_PATH`: 🟢 успех / 🔴 ошибка / 🟡 прочее, 🖼️ — были картинки; дата / префикс базы / количество |
| `other_sendTestMessage` | только `admin` | список пользователей из БД inline-кнопками |

Эти команды срабатывают только на точный текст.

| Inline-кнопка | `callback_data` | Что делает |
|---|---|---|
| `<имя> (<роль>)`, по 2 в ряд | `other_sendTest_<user_id>` | отправляет выбранному пользователю тестовое сообщение и присылает отправителю статус: 🟢 отправлено (с `message_id`) или 🔴 ошибка. Роль `admin` проверяется повторно |

## Уведомления без команды

- **Новые операции.** `kofd_updater` публикует новые чеки в NATS (subject `new_transactions`). Бот присылает каждому пользователю сообщение «Новые транзакции:» с кнопкой `чек №<id> / <сумма>₸` (`getCheck_<id>`). `kaspi_manager` получает только продажи товаров с признаком `kaspi_in_sale`.
- **Брокер недоступен.** Если бот потерял связь с NATS, все пользователи с ролью `admin` один раз получают «⚠️ Брокер сообщений недоступен…».
